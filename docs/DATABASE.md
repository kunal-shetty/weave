# Promptify — Database Schema

## Overview

Promptify uses a dual-store architecture:

1. **MongoDB** — Primary store for all application documents (Sections, Elements, ReviewItems, Sessions, WorkspaceMembers)
2. **Supabase (PostgreSQL)** — Mirrors lightweight metadata for fast KV lookups, stores auth data, and provides real-time capabilities

## Why MongoDB + Supabase?

**MongoDB** is the primary store because:
- Document model fits heterogeneous schemas (Sections have JSX, Elements have loops, Reviews have regions)
- Mongoose provides schema validation and auto-timestamps
- Aggregation pipeline for complex queries (though not heavily used yet)
- The problem statement allows MongoDB or file-based JSON

**Supabase** mirrors metadata because:
- Fast KV lookups without MongoDB queries (e.g., `field_id → section_id`)
- Provides OAuth auth (Google, GitHub) without building it ourselves
- Real-time subscriptions can push CMS updates to clients
- The `field_kv` table serves as a lightweight content CDN
- Free tier is generous for hackathon use

**Why not just Supabase?** MongoDB's document model is more flexible for the complex nested schemas (Cards loop arrays, review regions, generated JSX). Supabase is better for auth and fast lookups. They complement each other.
